## 三、机器可读任务图与持久状态

`remaining-work-plan.json` 固定包含 65 个 Work ID：

```text
BOOT 3
SEC 7
HIST 8
CLI 13
WEB 11
DESK 11
STB 12
```

每项字段：

- `id`：Work ID；
- `order`：唯一排序；
- `depends_on`：只有全部 PASSED/正式 WAIVED 才能解锁；
- `executor`：local-ai / owner / owner+local-ai；
- `irreversible`：是否不可逆；
- `authorization_required`：是否必须 Owner 固定格式授权；
- `status`：READY/LOCKED/IN_PROGRESS/BLOCKED/FAILED/PASSED/WAIVED。

选择规则：

```text
下一任务 = 依赖全部完成的未完成任务中 order 最小的一项
```

持久状态必须形成唯一前沿：

- 已完成任务连续位于前部；
- 当前只有一个 READY/IN_PROGRESS/BLOCKED/FAILED；
- 后续全部 LOCKED；
- PASSED 必须有 evidence 文件、PR number、最终 Head SHA 和 merge SHA；
- IN_PROGRESS 必须有 branch/started_at；
- BLOCKED 必须有 reason/required_input/owner_action；
- FAILED 必须有 evidence_file/root_cause/next_action；
- SEC、HIST 和不可逆任务不得 WAIVED。

validator 会拒绝跳步、双前沿、无证据 PASSED、依赖未完成解锁和状态元数据缺失。

## 七、重要防错规则

1. 一次只执行一个 Work ID。
2. 没有退出码、日志、artifact digest 或真实环境证据，不得 PASSED。
3. 失败必须定位根因，不能只重跑到绿色。
4. Secret 不得进入 GitHub、日志、命令参数或聊天。
5. 旧凭据必须在撤销后真实认证失败，不能只看 revoked 状态。
6. Git 历史 force push 必须有固定格式 Owner 授权、备份和回滚 bundle。
7. 推任何 Tag 前必须计算会触发哪些 workflow；发现跨 Workflow 冲突先修触发规则。
8. 自动测试不能替代物理 Mac、真实模型和真实用户。
9. 未获明确版本/Head/channel 授权，不得公开发布。
10. Stable 必须签名、公证、staple，并在干净 Mac 无绕过启动。
11. 状态更新必须与证据、台账和后继解锁在同一 PR 中保持一致。
