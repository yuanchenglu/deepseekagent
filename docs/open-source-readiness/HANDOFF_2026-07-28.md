# 三、当前唯一第一优先任务

先处理 `.github/workflows/release-electron-preview.yml` 的正式发布 concurrency 风险，不要并行启动 Runtime Lease 或其他新任务。

当前风险代码：

concurrency:
  group: electron-preview-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

问题：新的 `workflow_dispatch + publish=true` 正式运行可能取消正在执行的正式发布。发布流程会先创建/更新 GitHub prerelease，再提升 R2 Preview channel；中途取消可能导致两个公开渠道状态不一致。

必须实现的契约：

1. 同一 PR 的新提交可以取消旧的 PR 验证。
2. 正式发布必须串行。
3. 正在执行的正式发布不能被后续运行取消。
4. PR 验证与正式发布的 concurrency group 必须清晰分离。
5. 不得改变当前无签名 Preview、版本、Tag、Manifest、SHA-256 和 publish=true 的发布边界。

## 分支策略

开发分支为 `develop`，发布分支为 `master`。`develop` 分支已取消 PR 强制保护，可以直接推送。

## 执行优先级

### 第一优先：走 PR 流程

1. 创建功能分支 → 提 Pull Request → 等待 CI 通过 → 合入 `develop`
2. 按项目 `docs/` 目录下的计划文档执行任务
3. 确保 PR 标题和描述清晰说明变更内容

### 第二优先：异常处理与直推

如果 PR 流程持续出问题，例如 CI 环境不可用、测试依赖无法安装、规则冲突：

1. 先分析原因：定位根因，确认是代码问题还是环境问题
2. 尝试修复：如果是代码问题，例如缺少文件、配置错误，直接修复
3. 解决不了才直推 `develop`：如果问题无法在当前环境解决，直接推送到 `develop`，但不得无说明绕过流程

## 直推 develop 的纪律

### 1. Commit 信息格式

Commit 信息必须包含「问题原因」和「技术债务」段落：

<type>(<scope>): <变更说明>

## 问题原因
[写明为什么 PR 流程无法通过，根因是什么]

## 技术债务
- [列出本次遗留的未解决问题、待办事项]

示例：

feat(auth): add login ticket validation

## 问题原因
CI 环境的 Playwright 依赖版本与本地不一致，E2E 测试在 CI 上无法运行。已手动验证本地通过。

## 技术债务
- Playwright 版本锁定需要统一管理
- E2E 测试在 CI 上需要单独排查

### 2. 技术债务记录（二选一）

方式 A：记在 Commit 信息里（推荐）

- 在 Commit 的「技术债务」段落用短横线列表写明
- 后续接手者根据 Commit 信息判断是否需要处理

方式 B：记在项目文档中

- deepseekagent → `docs/TECH_DEBT.md` 或 `docs/BUG_LIST.md`
- deepcode → `docs/BUG_LIST.md`
- deepseek_runtime → `docs/TECH_DEBT.md`
- oh-my-deepseek-harness → `docs/TECH_DEBT.md`
- llm-harness-agent → 根目录 `TECH_DEBT.md`
- 每条格式：`[日期] 描述 | 遗留原因 | 状态`

## 核心原则

- 能走 PR 就走 PR，直推是兜底方案，不是默认方案
- 直推必须有交代：Commit 要说明为什么绕过 PR，以及留下了什么
- 技术债务不怕有，怕没人知道；记下来才可追踪
