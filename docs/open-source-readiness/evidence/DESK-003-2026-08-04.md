## 二、发现并修复 P0 bug：--no-open 无效参数（PR #55）

### 根因
`mode-manager.ts:169` 传 `--no-open` 给 `opencode serve`，但 opencode serve 不识别该参数，导致参数解析失败打印 help 而非启动服务器。DeepCode 模式无法启动。

### 验证
```bash
# 带 --no-open（原代码）：打印 help，HTTP=000，无 "server listening"
opencode serve --hostname 127.0.0.1 --port 41779 --no-open
# → 打印 help，HTTP=000（失败）

# 移除 --no-open（修复后）：正常监听
opencode serve --hostname 127.0.0.1 --port 41778
# → "opencode server listening on http://127.0.0.1:41778"（HTTP 200）
```

### 修复
移除 `--no-open` 参数（opencode serve 默认不打开浏览器）。

- mode-manager.test.ts: 9/9 通过 ✅
- desktop main 全部: 47/47 通过 ✅
