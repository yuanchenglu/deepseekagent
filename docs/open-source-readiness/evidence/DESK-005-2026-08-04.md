## 二、单元测试覆盖（35 个测试通过）

### Workspace Lock（无双写核心）
- 同一 workspace 只允许一个 writer ✅
- reader-reader 并行 ✅
- reader-writer 双向互斥 ✅
- 任务升级自己的读锁（仅当唯一 reader）✅
- 其他 owner 不能释放同 taskId 锁（所有权隔离）✅
- 只释放被销毁 owner 的租约 ✅
- 完成的任务释放所有 workspace ✅
- 拒绝畸形 task/owner 标识 ✅

### Runtime Task Lease（orphaned + 恢复）
- 畸形 payload fail-closed ✅
- reader-writer / writer-writer 冲突拒绝 ✅
- acquire + event replay 幂等，拒绝 eventId 复用 ✅
- 续租 + 过期 heartbeat 不复活 ✅
- orphaned lock fail-closed 直到显式恢复 ✅
- process-exit 作为 orphan 权威恢复证据 ✅
- DeepAgent/DeepCode 各自 runtime 身份绑定 ✅
- 权威状态迁移不暴露可变快照 ✅

### Runtime Task Supervisor（crash + 恢复）
- 绑定真实进程证据，释放冲突，安全复用外部 task ID ✅
- 幸存 PID 证据恢复为 orphaned，要求显式验证后 resume ✅
- 拒绝未认证调用者 ✅
- Main 重启后同 socket 路径接受新 RPC ✅

### Runtime crash 语义
- Runtime heartbeat 过期 → orphan 所有该 Runtime 的 active task ✅

## 三、生产级 dual-runtime E2E（6 个测试通过）

使用生产客户端 `acquireRuntimeTaskLease()` + 真实 `RuntimeTaskSupervisor`：

1. **读写冲突 + 无双写**：spawn 前冲突拒绝，无 workspace 副作用；完成/取消后释放 ✅
2. **Runtime heartbeat 超时 fail-closed**：不影响健康 Runtime 或其他 workspace ✅
3. **共享 bridge crash + DeepCode child crash + PID 重用**：无跨 Runtime 损害 ✅
4. **Main 重启后 orphaned 恢复**：仅匹配进程证据才 resume ✅
5. **orphaned acquire-before-bind 释放**：显式 Runtime terminal 确认后释放 ✅
6. **heartbeat orphaned 后恢复**：无 PID 的 Main 重启任务保持锁 ✅
