# OpenCode Go 成本核算方法论

## 核心公式

```
每次请求总 tokens = 未缓存输入 + 缓存输入 + 输出(含推理)
总成本 = 各项 tokens × 对应单价
```

## OpenCode Go 典型请求模式（官方数据）

### DeepSeek V4 Flash（max 推理）
| 项目 | tokens | 单价 (USD/1M) | 单次请求成本 |
|------|--------|--------------|------------|
| 未缓存输入 | 790 | $0.14 | $0.00011 |
| 缓存输入 | 68,000 | $0.0028 | $0.00019 |
| 输出（含推理） | ~448 | $0.28 | $0.00013 |
| **合计** | **69,238** | | **$0.00043** |

### 关键认知：输出占比不到 1%

```
输出占比 = 448 ÷ 69,238 = 0.65%
```

即使 max 推理让输出涨了 60%，总成本只多了 $0.00013 × 0.6 = $0.00008，可以忽略。

## 缓存是命根子

缓存命中率决定了实际成本。实测证据（2026-06-10）：

同一 system prompt + user message，连续发两次：
- 第 1 次：cached_tokens = 0（全量计费）
- 第 2 次：cached_tokens = 256 / 307（83% 命中）

**缓存是 OpenCode Go 服务端自动处理的，Agent 端不需要做任何事。** OpenCode Go 检测同一 API Key 的请求前缀是否重复，重复则从缓存取。
