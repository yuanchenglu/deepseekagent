# Feishu 表格渲染修复验证测试提示词

修复 Feishu markdown 表格渲染问题后，向目标机器人发送以下提示词验证效果。

## 标准验证提示词

> **【测试】请回复一段包含以下 Markdown 元素的测试内容，我需要验证飞书渲染效果：**
>
> 1. 一个 3 列 4 行的表格（包含中文、英文、数字）
> 2. 一段**加粗文字**和一段*斜体文字*
> 3. 一个有序列表
> 4. 一个无序列表
> 5. 一段 `行内代码` 和一个代码块
> 6. 一个二级标题
>
> 以上所有内容放到**同一条回复**里，不要分批发送。谢谢。

## 预期效果

发送该提示词后，机器人的回复应满足：

| 元素 | 预期表现 | 如果失败 |
|------|---------|---------|
| 表格 | 有格线、有列对齐、数据清晰 | 显示 `| 管道符 \|` 原始语法 |
| 粗体/斜体 | 文字有加粗/倾斜效果 | 显示 `**符号**` 或 `*符号*` |
| 列表 | 有序/无序列表有缩进和标记 | 显示 `- ` 或 `1. ` 原始符号 |
| 代码块 | 有灰色背景，等宽字体 | 显示 `` ``` `` 原始符号 |
| 代码片 | 标记区域内文字样式不同 | 显示 `` ` `` 原始符号 |
| 二级标题 | 字体更大更粗 | 显示 `##` 原始符号 |

## 纯表格测试（极端情况）

如果标准测试通过了，可以进一步测试纯表格场景（不含其他 markdown）：

> | 列1 | 列2 | 列3 |
> |-----|-----|-----|
> | 数据A | 数据B | 数据C |

这个场景在原始 bug 中也会触发 force-text 降级，因为 `_MARKDOWN_HINT_RE` 之前没有匹配 `|` 的模式。
