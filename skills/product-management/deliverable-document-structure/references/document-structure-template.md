# 文档结构模板

## 完整骨架

```markdown
# 文档标题 (English Title)

> 创建日期 / 上下文
> 关联文档 / 创新点索引

## 更新记录 (Update Log)

| 时间 | 更新内容 | 来源 |
|------|---------|------|
| YYYY-MM-DD HH:MM | 具体改了什么 | 谁/什么触发 |

---

## 目录

---

## §1 结论正文

（只保留当前正确版本。有讨论过程的结论标注 [→附录 Q#N]）

---

## §N 结论正文（续）

---

## 附录

### 附录 A：讨论债务

> 待讨论话题 [→ 详见 讨论债务文档]

### 附录 B：Q&A 过程记录

#### Q#1：问题标题
> 时间 | 提问 | 触发

**问题**：原始问题

**答案**：结论

> [→ 正文 §X 已体现此结论]

---
```

## 实际案例：Plan 架构深度分析文档

```
Plan架构深度分析-Plan-Architecture-Deep-Analysis.md (714行, 35KB)

  Header + Update Log ............ 36 行 ← 最稳定
  目录 .......................... 10 行
  §1-7 结论正文 ................. ~560 行 ← 修正时才变
    每个重要结论标注 [→附录 Q#N]
    交叉引用 [→创新点索引 I-NN]
  附录 A: 讨论债务 .............. 4 行  ← 引用外部
  附录 B: Q&A 过程记录 .......... ~105 行 ← 不断增长

  KV Cache 分析:
  - Header + 结论正文 ≈ 600 行 → 几乎不变 → 缓存全命中
  - Q&A 附录 ≈ 100 行 → 每次追加新 Q#N → 只尾部新增 Token
```

## 什么时候用这个结构

| 场景 | 是否使用 |
|------|---------|
| 架构深度分析 | ✅ 必须 |
| 产品对比分析 | ✅ 必须 |
| 技术方案（会被反复讨论） | ✅ 推荐 |
| 一次性报告 | ❌ 不需要 |
| 纯清单 | ❌ 不需要 |

## KV Cache 原理

```
前缀匹配 → 缓存命中 → 近乎免费 ($0.0036/M)

[Header + 结论正文 + Q#1..Q#5]  ← 旧部分 → 缓存命中
[Q#6]                            ← 新增部分 → 未命中 ($0.435/M)

错误做法：Q&A 散落在正文中间
[Header] [Q#1] [结论A] [Q#2] [结论B]
→ 插入 Q#2 → 结论A 位置偏移 → 结论A 缓存失效 → 成本爆炸
```
