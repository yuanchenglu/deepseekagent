# Single-Paper Translation Methodology

## 核心原则

**一篇一篇来，不并行，不中断。** 论文翻译具有连续性和连贯性，必须读完一篇、理解消化后再翻，翻完再做下一篇。

## 🔴 铁律：原汁原味，不得增减

**在语义层面，绝对不允许做任何精简、概括、省略或额外添加。** 原文有多少内容，翻译就必须覆盖多少内容。

- ❌ **禁止精简**：不允许把长段落压缩成摘要、不允许跳过任何章节或子节、不允许"限于篇幅此处省略"
- ❌ **禁止增加**：不允许添加原文没有的评论、分析、关联性解读、Harness 启示等额外内容
- ❌ **禁止概括**：不允许把详细实验描述概括为一句话、不允许把表格数据简化为文字叙述
- ✅ **可以调整**：词汇选择、语序调整、长句拆分——但这些是表达层面的调整，不改变语义覆盖范围
- ✅ **完整覆盖**：标题、作者、摘要、引言、方法论、实验、讨论、结论、附录——每部分都要翻译到位

**判断标准：** 如果用户把英文原文和中文翻译逐段对照，语义层面上不能发现任何缺失或新增的内容。禁止同时派发多篇论文给不同的子任务并行翻译。

**这是用户的硬性要求**，源于用户对并行批译质量的严厉批评（"你在干什么呀？我要的是论文的原文、论文的原文的完整翻译"）。用户明确说了"以后你让我翻译东西，你都应该按照这套模式来"。这不是偏好，是铁律。

**全文翻译，不是摘要翻译。** 用户要的是论文正文的完整翻译（含所有章节、表格、公式），不只是摘要和元数据。只翻摘要会被视为未完成。

## 触发条件

**当你被要求翻译论文时，必须先加载此 skill。** 适用于学术论文、技术报告、技术白皮书等需要保持上下文连贯性的文档。用户请求中若出现"翻译"+"论文"关键词，自动触发。

不适用于：单段文本翻译、对话翻译、即时短文本翻译。

## 步骤

### 第1步：确认原文格式

检查目标文件是 PDF 还是其他格式：
- **PDF** → 使用 **PyMuPDF（fitz）** 提取，不用 pypdf/pdfplumber（PyMuPDF 保留文字间距和表格结构更好）
- **Markdown/Text** → 直接读取

### 第2步：PDF → 英文 Markdown 转换

使用 PyMuPDF 的固定脚本（参考 `references/pdf2md.py`）：

```python
import fitz
doc = fitz.open(pdf_path)
page_count = doc.page_count  # 必须在 doc.close() 前读取
md_lines = []
for page in doc:
    # 使用 TEXT_PRESERVE_WHITESPACE 标志保留文字间距
    blocks = page.get_text("dict", flags=fitz.TEXT_PRESERVE_WHITESPACE)["blocks"]
    # 处理文本块...
    # 表格检测：page.find_tables() 尝试提取 Markdown 表格
    tables = page.find_tables()
    if tables and tables.tables:
        for t in tables.tables:
            t_data = t.extract()
            # 渲染为 Markdown 表格
doc.close()
```

**注意：** `doc.page_count` 必须在 `doc.close()` 之前读取，否则会抛出 `ValueError('document closed')`。

保存为 `en-md/` 目录下的 `.md` 文件。

**表格提取说明：** PyMuPDF 的 `find_tables()` 能检测到部分 PDF 表格（表格有明确边框线的情况）。许多学术论文的"表格"实际上是按空格对齐的文本而非 PDF 表格对象，这些不会被检测到。翻译时需手动从文本中识别并重建表格结构。

### 第3步：通读全文

完整阅读英文 Markdown，理解：
- 论文标题、摘要、结构（各章节内容）
- 核心贡献和方法论
- 表格数据、公式、图表说明
- 实验结果和结论

**不读完不开始翻译。** 必要时可以分段读取大论文（50页+），但阅读完成后再统一翻译。

### 第4步：逐节翻译为简体中文 Markdown

翻译原则：
1. **保持学术语气**，专业术语准确一致
2. **表格还原为 Markdown 表格格式**（`| col1 | col2 |`），不丢失行列结构
3. **数学公式保留原始格式**（LaTeX 或 Unicode）
4. **代码示例保留原始代码**，仅翻译注释
5. **参考文献保留原始英文格式**（不翻译文献条目）
6. 技术术语首次出现时中英文对照（如"缩放定律 Scaling Laws"）
7. 英文专有名词（模型名、数据集名、方法名）保留原文
8. 翻译要完整——**不得跳过任何章节**，包括附录

### 第5步：保存并验证

- 保存到 `zh-md/` 目录，同名 `.md` 文件
- 验证：文件开头（标题、作者）和结尾（结论、参考文献）完整
- 检查表格格式正确（分隔线对齐）
- 确认所有章节已覆盖

### 第6步：报告完成

向用户汇报：
- 论文标题和页数
- 翻译流程（PDF提取→通读→逐节翻译）
- 覆盖的章节范围
- 输出位置和文件大小

**Harness 关联分析。** 如果翻译的论文属于 LLM+Agent/Harness 相关领域，翻译后需附上与 Harness 理论的关联分析——将论文的核心贡献映射到 Harness 六组件（E/T/C/S/L/V）或相关概念。用户在做 Agent Harness 研究，这个关联分析是他使用翻译价值的关键部分。

**批量翻译的 README 导航。** 如果一次翻完多篇论文，所有翻译完成后需生成 README 导航文件，包含：
- 每篇论文的中文标题、发表时间、出处
- 简短摘要
- 与 LLM+Harness=Agent 研究的关联度评分（⭐1–5）
- 完整的文件目录结构

**追加模式：添加到已有集合。** 如果只翻译一篇论文并添加到已有集合，不要创建新 README，而是更新原有的 README：
1. 将新论文按时间插入列表
2. **排序规则：最新论文在最上面，最老论文在最下面**（这是用户的固定偏好）
3. 重新编号所有条目（从 #01 开始连续编号）
4. 更新快速索引表格，添加新行的同时保持整体降序
5. 更新文件结构示意图，标记新文件为 `← 新增`
6. 更新交叉分析表（Harness 组件映射）——如果新论文提供了新的视角，补充到对应组件行
7. 更新底部的"最后更新"日期

**诊断提示：find_tables() 输出解读。** 转换后脚本会打印 `~N table rows`。如果 N=0，说明该 PDF 的表格是文本对齐而非 PDF 表格对象，翻译时需从文本中手动识别并重建 Markdown 表格。这一输出本身就是重要的诊断信号——不要忽略它。

## 陷阱与注意事项

- ❌ **不要并行派发**：多篇论文同时翻译会降低每篇的质量一致性。这是用户明确纠正过的错误。
- ❌ **不要用 pypdf 提取表格**：它不检测表格结构，表格数据会变成散乱文本。即使用了 pypdf，也要知道表格数据会丢失。
- ❌ **不要跳过通读步骤**：不读完就翻译会导致术语不一致、上下文断裂。用户明确要求"读英文原文→理解消化→翻译"这个流程。
- ❌ **不要用 OCR**：PDF 内嵌文本提取即可，OCR 引入乱码风险。
- ❌ **不要只翻译摘要**：这是被用户最严厉纠正的错误。用户说"你在干什么呀？我要的是论文的原文、论文的原文的完整翻译、论文原文正文的原本翻译的完整翻译。那你不是，你给我那个paper点zh，那只是翻译的摘要啊"。**全文正文（含所有章节、表格、公式、附录）必须翻译**，不可只做摘要/元数据翻译然后说"已完成"。
- ❌ **不要用并行批译替代逐篇精译**：即使任务量大，也必须一篇篇来。用户明确要求对比两种方式的质量，并行批译的质量差距已被用户证明不足。
- ✅ 一篇翻译完成并报告后，再开始下一篇。
- ✅ 大论文（50页+）可分段读取，但翻译时保持章节完整性。
- ✅ 表格以 `| --- |` 格式还原，先写表头分隔行，再填数据行。
- ✅ 翻译完成后告知用户哪几篇是哪种方式。
- ✅ 用户满意当前质量后（确认"质量非常高"），继续按同样方式翻下一篇。

## 输出目录结构

```
papers/
├── pdf/           # 原始 PDF
├── raw-txt/       # 临时提取的文本（可选清理）
├── en-md/         # 英文 Markdown（PyMuPDF 转换后）
└── zh-md/         # 简体中文翻译（最终交付）
```
